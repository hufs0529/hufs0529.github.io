## 처리 축은 하나 — 리랭킹 깊이 d

`d` = 크로스 인코더가 다시 점수를 매기는 밀집 검색 후보의 수. 그중 상위 3개가 프롬프트에 들어갑니다.

| d | 하는 일 | 역할 |
| --- | --- | --- |
| **0** | 밀집 검색 상위 3개를 그대로 사용 | 기준 |
| **3** | 밀집 검색이 이미 고른 3개의 **순서만** 바꿈. 새 문서는 못 들어옴 | **순서 통제군** |
| 7 · 10 · 25 | 상위 d 개를 다시 매겨 최고 3개 | 처리 |
| **50** | 후보 풀 전체를 다시 매겨 최고 3개 | 처리 (최대 용량) |

- 모든 조건이 **정확히 문서 3개** 를, **같은 top-50 후보 풀** 에서 고릅니다. 조건 사이의 차이는 *고르는 데 쓴 연산량* 하나뿐입니다.
- 7 과 25 는 중간에 추가했습니다. 깊이 사다리가 너무 성겨 경향을 볼 수 없다는 멘토 피드백 때문입니다.
- **왜 리트리버 크기가 아니라 깊이인가?** 깊이는 **질의마다 반복되는 비용** 이라 라운드마다 반복되는 통신과 같은 단위로 맞바꿀 수 있습니다. 더 큰 인코더는 한 번 내는 인덱싱 비용이라 비교가 어렵습니다.

### d = 3 이 필요한 이유

긴 문맥에서 같은 문서라도 **순서** 가 바뀌면 답이 달라진다는 연구(Lost in the Middle)가 있습니다. 그래서 *순서만 바뀐* 효과와 *더 좋은 문서가 들어온* 효과를 나눠야 합니다. 이를 위해 두 값을 따로 기록했습니다.

| 지표 | 의미 |
| --- | --- |
| **promotion rate** | 밀집 검색만으로는 뽑히지 않았을 문서가 프롬프트에 들어간 비율 → *새 문서* |
| **rank-change rate** | 기준과 다른 문서가 그 자리에 있는 비율 → 순서 변경 포함 |

d = 3 은 promotion 이 구조적으로 0 이고, 코드에서도 `promotion_rate == 0` 을 단언합니다.

## 고정된 배경 조건

| 구성 요소 | 선택 | 이유 |
| --- | --- | --- |
| 기본 모델 | SmolLM2-135M-Instruct | 과제가 새 지식이 아니라 근거 찾기 |
| 어댑터 | LoRA r=8, attention projection 만 | 학습 파라미터 92만 개 = 클라이언트 · 방향당 1.84 MB (fp16) |
| 클라이언트 | 8개, 전원 참여, FedAvg | cross-silo 규모 |
| 파티션 | 같은 크기 · **주제 분리** (Dirichlet 아님) | 설계를 1차원으로 유지 |
| 질문 | NQ-open (학습 87,925 · 검증 3,610) | 짧은 추출형 답 |
| 코퍼스 | DPR `psgs_w100` 에서 20만 문단 | gold + BM25 hard negative + 무작위 |
| 임베딩 | bge-small-en-v1.5 (동결), 클라이언트별 Qdrant 컬렉션 | |
| 리랭커 | ms-marco-MiniLM-L-6-v2 | 6층 증류 모델, 제한된 기기에서도 현실적 |

**왜 Dirichlet 파티션을 쓰지 않았나?** Dirichlet 은 *주제 편중* (의도)과 *클라이언트 데이터 크기 불균형* (의도하지 않은 집계 불안정)을 함께 바꾸고, 시드마다 다시 뽑혀 시드로 안정화하려는 추정값에 분산을 더합니다. 그래서 클라이언트 이질성은 **요인이 아니라 고정된 배경 조건** 으로 두고, 같은 크기의 주제 분리 파티션 2개를 시드에 번갈아 배정했습니다. 시드 수가 짝수여야 해서 5개가 아니라 4개입니다.

## 측정의 두 가지 문제와 그 답

### ① 라운드 수는 너무 거친 자다

LoRA 는 학습 파라미터가 적어 몇 라운드면 수렴합니다. *수렴하면 멈추는* 실험으로는 이 규모에서 처리 효과를 구분할 수 없습니다.

→ **모든 실행이 똑같은 통신 예산(1.74 GB, 59 라운드)을 쓰고, 조기 종료가 없습니다.** 목표 도달 라운드는 학습 곡선을 **선형 보간** 해서 구합니다. 결과가 정지 규칙에 좌우되지 않습니다.

### ② 라운드는 자유 변수가 아니다

`R = S / K` (S = 전체 로컬 스텝, K = 라운드당 로컬 스텝). K 는 집계 전에 클라이언트가 얼마나 멀리 떠내려가는지(드리프트)를 결정합니다.

→ K 와 S 는 관례가 아니라 **기록된 파일럿(게이트 ③)** 으로 정했습니다.

## 평가는 모두 d = 0 문서로

어떤 깊이로 학습했든 **평가는 d = 0 문서** 로 합니다. 리랭킹이 점수를 올리는 길은 두 가지이기 때문입니다.

| 경로 | 무엇이 좋아지나 | 라운드를 줄이나 |
| --- | --- | --- |
| **학습 경로** | 더 좋은 문서로 학습해 더 좋은 모델 | ✓ 줄인다 → 바이트 절감 |
| **서빙 경로** | 추론 때 더 좋은 문서를 받음 | ✗ 영원히 매 질의 리랭킹 필요 |

자기 깊이로 평가하면 두 경로가 합쳐져 구별할 수 없고, d = 50 의 평가 문서 품질은 d = 0 보다 3.92%p 높았습니다. 섞었다면 **없는 통신 절감을 만들어 냈을 것** 입니다. 대신 보고 점수가 실제 배포보다 낮고, 비용 모델에서 서빙 이득을 0 으로 잡는 *리랭킹에 불리한* 회계라는 점을 한계로 명시했습니다.

## 파일럿 게이트 3개

본 실험 전에 싸게 돌리고, 각각 **미리 정한 통과 기준과 실패 시 행동** 이 있습니다. null 결과가 나왔을 때 *설정이 부적절했다* 가 아니라 *처리 탓* 이라고 말할 수 있게 하기 위해서입니다.

| 게이트 | 필요한 것 | 통과 기준 | 실패하면 | 결과 |
| --- | --- | --- | --- | --- |
| ① 성능 여유 | 학습 없음 | F1(정답 문맥) − F1(무작위 문맥) ≥ 5 | 더 큰 모델로 | **18.40** (19.57 vs 1.17) |
| ② 처리 단조성 | 검색만 | gold recall@3 이 d 에 따라 단조 증가 | 처리 축이 없음 → 깊이 재설계 | 0.467 → 0.5095, 처리 가능 비율 0.20–0.31 (기준 0.10) |
| ③ 로컬 스텝 보정 | 짧은 FL 탐침 | 드리프트가 측정되는 가장 작은 K | K 범위 재설계 | **K = 32, S = 1,892, R = 59** |

게이트 ③ 이 있는 이유를 한 문장으로 쓰면 이렇습니다. **드리프트를 줄여서 작동하는 처리는, 드리프트가 없는 곳에서는 관찰할 수 없다.** 첫 연구에서 local epoch 1 · 전원 참여로 드리프트가 거의 없는 설정에서 드리프트 상호작용을 찾으려 했던 실수를, 이번에는 설계 단계에서 막으려 했습니다.

게이트 ③ 의 탐침은 클라이언트당 250 질문에서 K = 4 를 가리켰지만, **전체 규모에서 다시 도출** 하니 K = 32 가 1라운드 발산이 가장 낮았습니다(0.3343). 작은 탐침의 결론을 그대로 믿지 않은 결정입니다.

## 곡선에서 교환비로

```mermaid
flowchart LR
  C[깊이별 학습 곡선<br/>시드 4개] --> I[목표 τ 도달 라운드<br/>시드별 선형 보간]
  I --> S[기준 대비 절감 라운드<br/>× 29.49 MB/라운드]
  S --> X[교환비<br/>절감 바이트 ÷ 리랭킹 FLOPs]
  X --> B[손익분기 대역폭<br/>대역폭 × 질의량 평면]
```

- τ 하나를 고르면 그 선택이 답을 정하므로 **τ 를 기준 곡선이 도달하는 범위 전체에서 훑습니다**(63개).
- τ 에 도달하지 못한 조건은 외삽하지 않고 *도달 못함* 으로 보고합니다.
- 비용은 **두 항 모델** 로 계산합니다: 한 번 내는 인덱싱 비용 + 질의마다 반복되는 `Q × d × FLOPs(크로스 인코더 쌍)`.
