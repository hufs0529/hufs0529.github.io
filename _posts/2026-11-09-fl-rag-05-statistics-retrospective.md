## 시드별 짝 비교

각 깊이를 기준과 **시드끼리 짝지어** 비교했습니다. 시드가 실행 전체의 라운드 수를 위아래로 밀기 때문에, 짝을 지으면 그 성분이 상쇄됩니다.

| | 차이의 표준오차 |
| --- | --- |
| 짝 없이 | 0.879 라운드 |
| **시드별 짝** | **0.16 – 0.47 라운드** |

보간도 **시드별로 먼저 하고 평균** 했습니다. 곡선을 먼저 평균하면 구간 추정에 필요한 시드 간 분산이 사라집니다.

## 스스로 찾아 고친 통계 규칙

| 항목 | 이전 | 고친 뒤 | 영향 |
| --- | --- | --- | --- |
| **판정 기준** | 코드는 1 × 표준오차, 글은 2 × 표준오차 (서로 다르고 둘 다 너무 관대) | 시드 4개 → 자유도 3 → **t(0.975, 3) = 3.182** | 기준을 통과한 목표 수가 26/10/16/9/7 → **5/0/1/1/5**. 유의해 보이던 d=10 vs d=0 (p=0.127)이 사라짐 |
| **판정 규칙** | 양수 절감이면 무엇이든 인정 | 63개 목표의 **과반** 에서 기준 통과해야 인정 | 표준오차 0.515 인 +0.0988 라운드 하나가 판정을 `no_effect` → `consistent` 로 뒤집던 문제 해결 |
| **교환비 계산** | 목표 하나에서 읽음 | 63개 목표의 **중앙값** | 두 깊이가 라운드 표와 반대 부호를 갖던 문제 해결 |
| **목표 격자** | 균일 격자 | 기준 곡선이 실제로 평가된 값들 | 균일 격자에서는 25점 중 15점이 0→1 라운드 구간에 몰려 절감이 정확히 0 으로 나옴 |
| **메커니즘 그림** | 이중 축 | 두 패널, 발산 축을 0 에 고정 | 0.77% 변화가 *붕괴* 처럼 보여 본문과 모순되던 문제 해결 |

결론의 **방향** 은 바뀌지 않았지만, 규칙이 틀렸고 이제 맞습니다. 모든 수정은 커밋 기록과 연구 기록 문서에 남겼습니다.

## 이 설계의 해상도 한계

짝 비교에서 분포 가정 없는 순열은 시드마다 부호를 뒤집는 것뿐이라 2⁴ = 16 가지이고, 가장 작은 양측 p 는 **0.125** 입니다.

| | 값 |
| --- | --- |
| 시드 4개로 도달 가능한 최소 p | **0.125** → p < 0.05 는 구조적으로 불가능 |
| 실제 관측된 최소 p | 0.127 (사실상 바닥) |
| 시드 6개라면 최소 p | 0.031 |
| 80% 검정력으로 검출하려면 필요한 효과 | 0.67 – 1.96 점 |
| 관측된 효과 | 0.03 – 0.60 점 |

**이 설계로는 어떤 크기의 효과도 유의하다고 선언할 수 없었습니다.** 이 한계를 분석 산출물의 `resolution_limit` 에 기록해서, `within_noise` 판정이 *못 찾았다* 가 아니라 *설계의 성질* 로 읽히게 했습니다.

## 계획 대비 변경

| 계획 | 실제 | 이유 |
| --- | --- | --- |
| 깊이 4 × 시드 5 = 20 실행 | 깊이 6 × 시드 4 = 24 실행 | 시드 5개는 파티션 2개를 3:2 로 불균형하게 배정. 깊이 7 · 25 는 멘토 피드백으로 추가 |
| 목표 정확도 하나 | 63개 sweep | 하나를 고르면 그 선택이 답을 정함 |
| 파일럿 K = 4 | K = 32 | 탐침은 클라이언트당 250 질문. 전체 규모에서 다시 도출 |
| 게이트 ② 300 질문 | 2,000 질문 + 엄격한 gold 규칙 | 포함 규칙만으로는 코퍼스 98% 가 gold |
| 더 큰 모델 8개 실행 | 도구는 만들고 테스트했지만 미실행 | 예상 GPU 28–40시간이 예산 밖. 나중에 바로 돌릴 수 있게 보존 |

## 한계

| 한계 | 내용 |
| --- | --- |
| **모델 규모** | 135M 하나. null 의 가장 그럴듯한 원인이자 다음 실험이 가장 먼저 바꿀 것 |
| **시드 4개** | p 바닥 0.125. 0.3점 효과를 80% 검정력으로 보려면 시드 약 16개 필요 |
| **곡선 미수렴** | 59 라운드 예산에서 대부분 50 라운드 이후 정점 → 초 · 중반 학습 구간에 대한 결론 |
| **통제군의 순서 효과** | d = 3 의 +0.31 ± 0.37 (p = 0.46)은 0 과 구별 안 됨. 같은 3문서를 여러 순서로 돌리는 조건은 미실행 |
| **한쪽으로 기운 회계** | 리랭킹의 배포 비용은 청구하고 배포 이득은 0 → 결론은 *학습 경로* 에 한정 |
| **가정한 기기 처리량** | 10¹² FLOP/s 가정. 실측 CPU 는 약 110 GFLOP/s 로 9배 낮아 통제군의 본전 영역은 더 좁아짐 |
| **시뮬레이션 클라이언트** | 실제 링크에서 측정하지 않고 모델링 |
| **정답 문자열 = gold 근사** | 정답 문자열을 포함한다고 근거 문서인 것은 아님 |

## 결론의 범위

> 135M 모델 · 1.74 GB 예산에서 리랭킹 깊이는 연합 파인튜닝의 통신을 되사지 못했다. 단, 이것은 *리랭킹이 비경제적이다* 가 아니라 *라운드를 줄이는 경로만으로는 리랭킹 연산 값을 치르지 못한다* 는 결론이다.

기여는 음수 부호가 아니라 **그 위치** 입니다. 사슬은 *더 좋은 문서 → 더 좋은 학습* 에서 끊어졌고, 다음 연구는 검색 깊이가 아니라 **모델 용량** 을 바꿔야 한다는 방향을 가리킵니다.

## 두 연구를 지나며 배운 것

| | 첫 연구 (FL × QLoRA) | 두 번째 연구 (FL × RAG) |
| --- | --- | --- |
| null 결과 | 설계가 드리프트를 거의 없애 상호작용이 나타날 수 없었음 | 처리는 작동했고, 끊어진 고리를 측정으로 특정 |
| 기전 측정 | 드리프트를 기록하지 않음 | 클라이언트 업데이트 발산을 기록 |
| 설정 검증 | 사후에 회고 | **파일럿 게이트 3개** 로 사전에 확인 |
| 통계 | 조합당 1회 | 시드 4개 짝 비교 + 해상도 한계 보고 |

첫 연구의 회고에서 적은 *다시 한다면* 목록(드리프트를 키우고, 측정하고, 시드를 반복한다)을 두 번째 연구의 설계에 반영했습니다. 연구를 하나씩 끝내는 것보다, **앞 연구의 실패가 다음 설계가 되는 과정** 을 경험한 것이 이 placement 에서 가장 큰 수확이었습니다.
